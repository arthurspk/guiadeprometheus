## :dart: O guia para alavancar a sua carreira

> Prometheus é o banco de dados de séries temporais e sistema de monitoramento open source mais usado do mundo: você instrumenta suas aplicações e serviços, ele coleta métricas em intervalos regulares (scrape) e você consulta tudo com PromQL, a linguagem de consulta criada especificamente para esse tipo de dado. Nascido no SoundCloud em 2012 e hoje o segundo projeto graduado pela CNCF (logo depois do Kubernetes), é o padrão de fato para observabilidade de métricas em times de DevOps, SRE e desenvolvimento — a peça central por trás de praticamente todo dashboard do Grafana. Este guia reúne documentação oficial, cursos gratuitos e pagos, livros, as ferramentas do ecossistema (Alertmanager, exporters, Thanos, Grafana Mimir) e um capítulo dedicado a usar IA na prática com o Prometheus, tudo verificado e organizado para quem quer sair do zero e chegar ao primeiro alerta em produção.

## 🤖 IA na prática

Prometheus e IA se cruzam de duas formas: usar assistentes de IA para trabalhar mais rápido com o Prometheus (escrever PromQL, criar regras de alerta, provisionar scrape configs) e usar o próprio Prometheus para observar sistemas de IA (latência de LLMs, custo de tokens, taxa de erro de agentes). Nos últimos dois anos surgiram diversos servidores MCP dedicados a conectar assistentes de IA diretamente a uma instância do Prometheus.

**Para aprender**
- Peça para um assistente de IA **explicar uma query PromQL** que você não escreveu (ou copiou de um dashboard pronto) linha a linha, incluindo o que cada função (`rate`, `histogram_quantile`, `increase`) está fazendo.
- Peça para **gerar 3 variações de uma regra de alerta** (limiar fixo, `predict_linear`, comparação com a semana anterior usando `offset`) e explique os trade-offs de cada uma.
- Cole a saída de `/metrics` de uma aplicação e peça sugestões de **quais métricas e labels fariam sentido** monitorar antes de escrever a instrumentação do zero.

**Para trabalhar**
- Servidores MCP como o [prometheus-mcp](https://github.com/prometheus/prometheus-mcp) (mantido pela própria organização do Prometheus no GitHub) e o [prometheus-mcp-server](https://github.com/pab1it0/prometheus-mcp-server) (o mais popular da comunidade) conectam assistentes como Claude, Cursor e GitHub Copilot diretamente à API HTTP do Prometheus — dá para pedir para a IA investigar um incidente lendo métricas reais, sem sair do editor.
- O [Grafana MCP Server](https://github.com/grafana/mcp-grafana) cumpre um papel parecido para quem consulta métricas do Prometheus através do Grafana: conecta o assistente a dashboards, datasources e alertas.
- Use IA para gerar **scrape configs e regras de relabeling** a partir de uma descrição do ambiente (ex.: "quero descobrir pods com a label `app=checkout` via Kubernetes SD") — essa é uma das partes mais propensas a erro manual do `prometheus.yml`.
- Depois de qualquer alerta gerado por IA, **valide manualmente a query na aba Graph/Expression browser do próprio Prometheus** antes de colocar em produção — um `sum by` errado ou um `rate` no intervalo errado gera alertas silenciosos ou barulho excessivo.

**Limites e boas práticas**
- IA erra a sintaxe do PromQL com frequência, principalmente em funções menos comuns (`label_replace`, `absent`, joins com `on`/`group_left`). Sempre teste a query antes de salvar a regra.
- Cuidado com sugestões de IA que criam **labels de alta cardinalidade** (ex.: usar `user_id` como label) — isso é uma das causas mais comuns de Prometheus derrubado por excesso de séries temporais, e a IA não tem como saber o volume real dos seus dados.
- Não conecte um servidor MCP com acesso de escrita (`--web.enable-admin-api`) a um assistente sem revisar as permissões — prefira sempre acesso de leitura.
- Entenda o alerta antes de ativá-lo: uma regra gerada por IA que dispara errado às 3h da manhã é problema seu, não da IA.
